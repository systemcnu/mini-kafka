# SL4 Slice Design — Hostile inputs & caps audit

**Status: FINALIZED (2026-07-29) after 2-seat independent review (buildability + different-model coverage) — 14 findings (9+5, two convergences: the SHUTTING_DOWN elicitation is terminal and cannot share the battery's live broker; the over-cap frame-writer goroutine needs explicit shutdown accounting), all integrated, none left open. Worst catches: the "audit that cannot go stale" as drafted could not detect a forgotten constant (density derives max from the very list being audited); the design claimed "a well-behaved client reconnects" when this repo's own client redials only on timeout — idle reclaim would have shipped a landmine for any app that pauses >5 min.**
**Derives from: SPEC v1.0.1 · DESIGN v1.0.1 · SLICES v1.0.1 (hashes in STATUS.md).** Scope authority: SLICES §2/SL4. Mechanisms: DD-16 (cap inventory), DD-17 (error registry), DD-18 (names), DD-24 (edge enforcement), referenced never restated.
**Done =** scenario H real: a scripted battery throws every hostile input class at live brokers — every one answered by its named stable code, the broker still serving after each non-terminal one — and the registry is audited complete: every declared constant in AllCodes (parsed from source), every AllCodes entry elicited live, every cap backed by a rejection test, mechanically re-checked on every future `go test`.

## 2. Slice-local decisions

| # | Decision |
|---|---|
| D-SL4-1 | **The completeness audit is a two-leg chain that cannot go stale (F1-corrected: density alone audits the list against itself).** Leg 1 — `internal/wire` gains `AllCodes() []Code` maintained adjacent to the constants, plus a wire test that PARSES `errors.go`'s const block (stdlib `go/parser` on the package's own source) and asserts every declared `Code` constant appears in AllCodes() — so a new constant that skips AllCodes fails immediately, which a density check over AllCodes-derived bounds structurally cannot catch. Leg 2 — the battery (`internal/broker/registry_test.go`, real TCP on `127.0.0.1:0`) elicits every AllCodes() entry from live brokers and asserts elicited == AllCodes(). **Battery structure pinned (F2/CF2 convergence):** one shared OSFS broker for the 11 non-terminal codes · WRITE_FAILED on a dedicated `newWithFS` FaultFS broker with the fault suffix scoped to the target topic's own log path (`<topic>/0/log` — an unscoped `"log"` suffix would fire on any partition and sticky-degrade it under later subtests, F4) · SHUTTING_DOWN last, on a dedicated throwaway broker: open a conn, run Stop() concurrently, hammer requests collecting responses until EOF, assert ≥1 code-10 frame observed (no existing test elicits 10 over the wire — the draft's "shutdown_test.go pattern" citation was false, F2; the drain window is racy, so the assertion is ≥1-of-many, never exactly-once). Union of elicitations across instances == AllCodes(). Consequence: any future slice adding a code without teaching the battery goes red — SD-8's "SL4 audits completeness" becomes a standing property, and SL6's PROTOCOL.md diff (PROT-1) gets its machine-readable registry for free. |
| D-SL4-2 | **Conn cap now serves its frame (DD-24's "accept → write error → close", replacing SL0's silent close).** In acceptLoop, an over-cap accept spawns a short writer goroutine: `SetWriteDeadline(now+1s)` → write the CAP_EXCEEDED error frame → close. The goroutine + deadline are load-bearing: a hostile client that never reads would otherwise wedge acceptLoop itself. **The writer is `s.wg`-tracked (F7/CF5 convergence):** `s.wg.Add(1)` before spawning — safe ordering, since Stop waits on acceptDone before wg.Wait — so Stop cannot return with a live writer holding an fd (a race-detector/goroutine-leak flake source otherwise). Over-cap conns never enter the registry, hold no slot, and are invisible to the coordinator. Existing TestConnectionCapGuard upgraded: the 257th conn now READS the CAP_EXCEEDED frame, then EOF. |
| D-SL4-3 | **Idle reclaim (DD-24): read deadline armed before each frame-wait; seam = `Config.IdleTimeout` (0 → 5 min default).** `SetReadDeadline(now+idle)` immediately before each ReadFrame — reclaims a conn after 5 min without a COMPLETE request, which also reclaims a slow-loris stalling mid-frame. Expiry → close, NO error frame (the peer is by definition not talking; writing at a dead peer can stall — G-SL4-1). The deadline never kills a parked fetch: parks happen in dispatch, AFTER the frame is read; no conn reads occur during a park, and the deadline is re-armed fresh on the next loop iteration — proven by an adversarial test with IdleTimeout < the fetch's maxWait. Response writes get `SetWriteDeadline(now+idle)`: a client that won't drain its response is the same leaked conn DD-24's reclaim exists to evict (without it, a stalled WriteFrame parks serveConn forever and the cap-protection claim is false). Heartbeating control conns are never idle by arithmetic (500 ms beats ≪ 5 min, D-SL2-11's exemption); ordinary consumers re-request within their ≤ 30 s maxWait. **The seam is a duration, not a Clock interface — a deviation from SLICES' locked "clock seam" wording, surfaced at this gate (CF1):** net.Conn deadlines run on wall clock; an injected Clock (the coordinator's pattern) cannot drive them; tests use ~200 ms. |
| D-SL4-4 | **Broker-level malformed table — the group-message rows SLICES names, plus every other type.** One table test over real TCP: for EACH body-bearing message type (Produce, Fetch, CreateTopic, JoinGroup, Heartbeat, CommitOffsets, LeaveGroup, GroupFetch) — truncated body → MALFORMED, trailing bytes → MALFORMED; ListTopics is the special case (its valid body is empty — truncation does not exist; its one row is "any non-empty body → MALFORMED", F6); plus the frame-level rows: below-min length, bad version, unknown type, oversized frame. Non-closing rejections assert the SAME conn then serves a valid request; closing rejections (frame-level: the stream is untrustworthy) assert a NEW conn serves — the split matches serveConn/dispatch reality (body-level MALFORMED is non-closing; frame-level closes). The wire-layer decode tables (messages_test.go) stay — they prove the decoder; this proves the SERVED frame and the broker's survival, which is what PROT-3's check text demands. |
| D-SL4-5 | **Group caps get their wire-level rejection tests (the audit's found gap).** Coordinator-level tests exist (coordinator_test.go); nothing proves the SERVED frame. Added: 33rd member's JoinGroup → CAP_EXCEEDED frame; 65th group's JoinGroup → CAP_EXCEEDED frame. **Timing budget on the record (F9):** raw-wire test conns never heartbeat and the coordinator's session timeout is a hardcoded 2 s — every cap-fill (32 joins; 64 group-joins) must complete inside one session window or swept members silently un-fill the cap and the over-cap join succeeds (a flaky-red under loaded CI). Sequential loopback joins run sub-ms so the budget holds with wide margin; the builder asserts the fill count immediately before the over-cap attempt so a sweep-race fails loudly, not silently. The group fill needs nowhere near 65 conns — one conn may hold joins in many distinct groups (the coordinator's conn binding is per-group); the builder verifies this at the coordinator seam before relying on it. |
| D-SL4-6 | **Registry deltas on the record, not silently absorbed.** (a) DD-17's locked list names 12 codes; the shipped registry has 13 — SHUTTING_DOWN (10) was SL0's graceful-stop addition under SD-8's each-slice-adds rule; PROTOCOL.md (SL6) documents the final set. (b) SLICES' SL4 row cites "SD-10's completeness pass" where the registry convention is actually SD-8 (SD-10 is the publication default) — a locked cross-reference misnumber, intent unambiguous, surfaced at this gate like SL3's DD-21 wording (no erratum cascade proposed). |
| D-SL4-7 | **What SL4 touches, counted honestly (CF3-corrected: the draft said "two behavior changes").** FOUR changes: (1) conn-cap served frame and (2) idle-reclaim read deadline — DD-24's own text; (3) response write-deadline — disclosed in D-SL4-3, justified under DD-24's cap-protection intent (a conn refusing to drain its response is a leaked conn); (4) ONE client change (F5): `GroupConsumer.Poll`'s existing redial path — today triggered only by `net.Error.Timeout()` — gains EOF/reset as a trigger for the FETCH conn, because idle reclaim is a new broker behavior and the shipped client must stay correct under it: an app that pauses Poll >5 min keeps its membership (the heartbeat goroutine never stops), loses only the idle fetch conn, and must not surface a spurious hard error for a still-valid member. Same redial machinery, one more trigger; membership/generation logic untouched. NO other client changes: idle `Producer`/raw-`Consumer` conns surface the error to the caller, who redials — stated in G-SL4-1 and in those types' doc comments. No new codes, no wire-format changes, no mk changes, no coordinator changes. |

## 3. Known gaps accepted

- **G-SL4-1** — idle-reclaimed conns are closed without an error frame (unlike the conn cap): the peer is absent by definition and a farewell write can stall. **This repo's own `Producer` and raw `Consumer` do NOT auto-reconnect (F5-corrected — the draft claimed "a well-behaved client reconnects"):** an app holding one idle >5 min gets an EOF/reset error on its next call and must redial; documented on both types. `GroupConsumer` is covered by D-SL4-7(4).
- **G-SL4-2** — in-flight requests per connection (NFR-2's inventory) has no rejection test because there is nothing to reject: DD-15's serve loop reads the next frame only after the response is written, so the cap (=1) is structural; a pipelining client's second request waits in the kernel buffer. Recorded in the audit table as "structural — by construction".
- **G-SL4-3** — response-frame cap is enforced by the receiving side (client's ReadFrame at MaxResponseFrame; wire-level rejection test exists) and respected by construction on the sending side (fetch budget accounting matches wire overhead exactly; ≤128 B non-record overhead ≪ 64 KiB headroom); no broker-side test forces an oversized response into existence. Audit table row says exactly this.
- **G-SL4-4** — PROTOCOL.md and its CI registry diff remain SL6's (SD-9); AllCodes() is built now so that diff has a stable hook.

## 4. Test plan mapped to claims

- **The battery** (`registry_test.go`, scenario H; structure per D-SL4-1): all 13 codes elicited live — UNKNOWN_TOPIC (produce to absent topic) · TOPIC_EXISTS (duplicate create) · BAD_PARTITION (produce AND fetch at partition ≥ count) · INVALID_NAME (hostile name with `../`) · MSG_TOO_LARGE (1 MiB+1 payload; bytes-unchanged assertion = PROD-3) · FRAME_TOO_LARGE (oversized frame) · MALFORMED (truncated body) · CAP_EXCEEDED (maxWait over cap) · FETCH_TOO_WIDE (17 entries) · STALE_GENERATION (commit at generation N−1 after a rebalance triggered from a second conn — same-conn re-joins are re-Joins by design and cannot go stale) · UNKNOWN_MEMBER (commit from a fabricated member) — then, on their dedicated instances: WRITE_FAILED (scoped FaultFS produce) · SHUTTING_DOWN (concurrent-Stop hammer, ≥1 frame before EOF). Completeness: union of elicited == AllCodes(). Broker-still-serving after every non-terminal elicitation.
- **AllCodes chain** (wire package): go/parser leg — every declared Code constant ∈ AllCodes() (F1); plus non-empty/no-duplicates sanity.
- **Conn cap frame:** 257th conn reads CAP_EXCEEDED then EOF; existing under-cap conns unaffected (D-SL4-2).
- **Idle reclaim:** idle conn reclaimed at short IdleTimeout · heartbeating GroupConsumer survives the same window (D-SL2-11's exemption, proven not asserted) · cap protection: fill the cap with idle conns, wait one timeout, a NEW conn is admitted and served · adversarial: IdleTimeout < fetch maxWait — the parked fetch completes and the conn survives (the deadline-never-spans-a-park proof) · stalled-reader (F3-corrected): the non-draining client requests a response of several hundred KB — well past loopback socket buffers, so WriteFrame genuinely blocks and only the WRITE deadline can free it (a small response would slip into kernel buffers and let the READ deadline pass the test with the write deadline unimplemented); red-with-write-deadline-removed is this test's sabotage form.
- **Paused-Poll redial** (D-SL4-7(4)): GroupConsumer pauses Poll past a short IdleTimeout; fetch conn is reclaimed; next Poll redials and serves records; membership never lapses (heartbeats continued).
- **Malformed table** (D-SL4-4): 8 body-bearing types × {truncated, trailing} + ListTopics' single row + 4 frame-level rows, served frame + survival asserted per row.
- **Group caps over the wire** (D-SL4-5), fill-count asserted before the over-cap attempt.
- **Bad-partition standalone rows (CF4):** produce-side exists (broker_test.go); a fetch-side bad-partition rejection test is added alongside the caps tests so the SLICES-bolded input has per-cap coverage outside the battery, sabotage-visible.
