# SL3 Slice Design — The demo

**Status: FINALIZED (2026-07-29) after 2-seat independent review (buildability + different-model coverage) — 13 findings (10+3, one convergence: the gated surface and the tested surface never coincided), all integrated, none needing adjudication. Worst catches: the narration required a client Assignment() accessor that didn't exist; Abandon()'s naive lifecycle either leaked the heartbeat goroutine or turned the "kill" into a 7-second polite wait; the public README still claims groups don't exist.**
**Derives from: SPEC v1.0.1 · DESIGN v1.0.1 · SLICES v1.0.1 (hashes in STATUS.md).** Scope authority: SLICES §2/SL3. Mechanisms: DD-20 (topology), DD-21 (external clock), D8 (Go-native visitor path), referenced never restated.
**Done =** scenario A real: a visitor types `go run ./cmd/demo`, sees messages flow inside 60 s from a cold cache, watches a consumer die and the survivor take over, all inside 3 minutes — measured by a clock the demo cannot see, gated in CI.

## 2. Slice-local decisions

| # | Decision |
|---|---|
| D-SL3-1 | **Topology (DD-20 realized).** One process: broker in-process on `127.0.0.1:0` (ephemeral — a second copy of the demo collides with nothing), data dir `os.MkdirTemp` cleaned on exit. Topic `demo`, 4 partitions. One producer goroutine (shipped `client.Producer`, ~20 msg/s, payloads `msg-<n>`) + two `client.GroupConsumer`s ("consumer-1", "consumer-2") — all over real TCP. Act one: create topic, start everyone, narrate both consumers' ownership and first records; `#event first-flow` printed at the FIRST record any consumer receives. Act two: after ~5 s of visible flow, consumer-2 is killed ungracefully; the takeover is narrated (consumer-1's re-join and new 4-partition ownership, then records flowing from all 4); `#event done` printed at exit. Target in-process runtime ≈ 15 s — the 60 s budget belongs to `go run`'s cold compile, not to us. |
| D-SL3-2 | **TWO small public client additions (review F1 found the second was silently required).** (a) `GroupConsumer.Abandon()` — the DD-20 kill: sequence PINNED (F3): close both raw conns LOCK-FREE (that is the kill instant, and a concurrent `net.Conn.Close` is what unblocks the member's own Poll parked up to 7 s holding the fetch mutex — taking a mutex first would turn SIGKILL into a polite wait) → `close(hbStop)` → wait for the heartbeat goroutine — all inside the closeOnce shared with `Close()`, so Abandon/Close are mutually idempotent and nothing leaks. Broker-side, only the CONTROL conn's drop is the death event (only Join binds connID→member); the fetch conn's drop is a no-op — stated so nobody wonders. (b) `GroupConsumer.Assignment() []uint32` — a snapshot of owned partitions under the client mutex: without it the demo cannot print its headline ownership lines at all (nothing else exposes assignment, and reaching into internals would break PROT-2). The demo diffs Assignment() after each Poll to narrate ownership changes. The 2 s heartbeat-silence path stays proven by SL2's SIGSTOP receipt — the demo narrates takeover, not deadline mechanics. |
| D-SL3-3 | **Narration discipline: legible, not a firehose — and DETERMINISTIC (F4).** Startup order pinned: create topic → start BOTH consumers → wait until the settled 2-member assignment is narrated (each consumer's ownership line printed) → only THEN start the producer. Consequence: ownership lines legitimately PRECEDE `#event first-flow`, and the transient consumer-1-owns-all-4 moment is settled before any record flows. Per consumer: one line per ownership change (diffed via Assignment()) + first-record-per-partition lines, then a per-second aggregate. Act headers (`— act one —`, `— act two —`) and the two `#event` lines are exact, greppable, on their own lines. `-ci` emits BYTE-IDENTICAL narration lines to the default (only terminal frills may differ, of which there are currently none) — asserted by the smoke test running both (F5/CF1). |
| D-SL3-4 | **External clock = `scripts/demo_timing.sh`, used by CI and by the macOS local leg (shell is harness, never visitor path — DD-21's own carve-out).** The script: export `GOTOOLCHAIN=local` + preflight that the local go satisfies go.mod BEFORE t0 (F6 — otherwise one go.mod patch-bump later, the gate silently measures a ~70 MB toolchain download) → make fresh temp `GOCACHE`/`GOMODCACHE` (never touching the caller's real caches) → note t0 → run `go run ./cmd/demo -ci` wrapped in `timeout -k` at ~200 s (F7: a hung demo fails FAST with a distinct exit + "timed out" receipt line, not at CI's 6-hour default), **timestamping in the DIRECT pipe reader** (`while read` + `date +%s`, NO filter stages between demo and timestamper — an interposed awk/sed block-buffers when piped and inflates every measurement, F9) → compute first-flow = t(`#event first-flow`) − t0 and total = t(`#event done`) − t0 → **gate: first-flow ≤ 60, total ≤ 180, non-zero exit on breach** → **assert the captured default-flow transcript carries the SAME ordered markers the smoke test pins (both act headers, ownership, takeover, both events) — the gated surface IS the tested surface (F5/CF1, the convergence finding)** → emit the receipt block (times, `go version`, OS identity, commit). 1 s resolution. Demo handles SIGTERM by cleaning its temp dir and exiting non-zero; cleanup is guaranteed on self-terminating paths only (SIGKILL leaves the dir — accepted, §3). |
| D-SL3-5 | **CI job `demo-timing` (DD-21) — container pinned BY DIGEST (F10/CF3).** `container: golang:1.24@sha256:<digest>` in the workflow: the digest becomes a fact of the committed workflow, the receipt echoes it verbatim (DD-21's "resolved image digest" satisfied EXACTLY — via workflow pinning rather than in-container observation, noted at the gate), plus `go version` + `/etc/os-release` as corroboration. Kills silent patch-drift between runs as a side benefit. Fresh checkout; runs the script; prints the receipt and uploads it as a build artifact. |
| D-SL3-6 | **The committed receipt = one REAL CI run's output, copied into the repo at this slice's exit.** CI gates every push forever but cannot commit to the repo; DD-21's "receipt committed as docs/receipts/demo-timing.txt" is satisfied by capturing the artifact of an actual run of this slice's CI (named commit inside) and committing it by hand — same pattern the benches will use (BENCH-3). The macOS leg (`demo-timing-macos.txt`) comes from running the same script locally. Staleness rule: the committed receipts name their commit; they are refreshed only when a slice materially changes the demo's startup path (recorded as a convention in the receipt header). |
| D-SL3-7 | **README top screen + correcting the now-FALSE body lines (CF2 — public-repo honesty).** The first screen: what this is (2 lines), the ONE command (`git clone … && cd mini-kafka && go run ./cmd/demo`), what the visitor will see (3 bullets incl. both acts + timings), CI badge only. AND: the body's directly-contradicted SL0-era lines are corrected NOW — "walking skeleton (slice SL0)" framing, "No consumer groups yet", and the manual-only Run-it block (groups shipped at SL2; the public repo must not advertise a rebalance demo above a body denying groups exist). The comprehensive README pass (R1/R2/R3, bench numbers) stays SL6/SL5 — this is the truth-only subset. |

## 3. Known gaps accepted

- **G-SL3-1** — the image digest is pinned in-workflow and echoed into the receipt, not observed from inside the container (in-container observation is impossible; the Actions container-init log corroborates). Floating-tag patch pickup is deliberately given up — refreshing the pin is a manual act.
- **G-SL3-2** — demo timing on macOS is a local clean-cache approximation, per DEMO-1's own check text; CI's macOS job stays build+smoke (SPEC's split, DD-21).
- **G-SL3-3** — the demo does not re-prove the 2 s heartbeat-silence detection (conn-drop death is instant); SL2's SIGSTOP receipt owns that proof. The demo narrates takeover, not deadline mechanics.
- **G-SL3-4** — committed timing receipts go stale by design between refreshes; each names the commit it measured (D-SL3-6).

## 4. Test plan mapped to claims

- **Demo smoke test** (`cmd/demo` gets a real test): run the BUILT demo binary twice — once default, once `-ci` — each with the short `-flow` override (a plain Go flag defaulting to the shipped value; no visitor or CI run ever takes the short path — the coverage seat cleared it) and `TMPDIR` pointed at a test-owned dir (F8 — how "temp dir removed" becomes assertable). Assert the transcript carries, in THIS order (F4-corrected): act one header · both consumers' ownership lines · `#event first-flow` · act two header · a takeover line showing consumer-1 owning all 4 (anchored AFTER the act-two header — the act-one transient owns-all-4 moment must not satisfy it) · `#event done`; exit 0; TMPDIR empty after; default and `-ci` narration lines byte-identical.
- **Timing-script test:** feed the script a FAKE demo emitting `first-flow` at ~2 s and `done` at ~4 s. Assert: passes with measured first-flow ∈ [2,4) (F9 — a harness that stamps at EOF measures ~4 and goes RED here) · fails non-zero when first-flow is scripted late · fails non-zero when total is late · fails distinctly on a hang (timeout path).
- **`Abandon()` unit (F2-corrected):** after Abandon, Commit returns a NON-NIL error (the conn is closed client-side — a literal code 13 cannot reach a closed socket; asserting 13 here would be unimplementable), and death is proven by the survivor owning all 4. The literal-13 proof already exists at SL2 (raw-wire stale-member commit).
- **Live legs (exit):** scenario A run locally (transcript receipt) · macOS clean-cache timed run (receipt) · the CI job's first real run green with its artifact captured into the repo.
