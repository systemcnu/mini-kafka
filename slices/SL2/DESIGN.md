## 2. Slice-local decisions

| # | Decision |
|---|---|
| D-SL2-1 | **Wire additions (types 9–17, additive only).** 9 JoinGroup `[str group][str topic]` → 10 JoinGroupResp `[str memberID][u64 generation][u32 n]{[u32 partition][u64 nextOffset]}` (join carries state, DD-14). 11 Heartbeat `[str group][str memberID][u64 generation]` → 12 HeartbeatResp `[u8 flags]` (bit0 = REJOIN, DD-11). 13 CommitOffsets `[str group][str memberID][u64 generation][u32 n]{[u32 partition][u64 next]}` → 14 CommitOffsetsResp empty. 15 LeaveGroup `[str group][str memberID]` → 16 LeaveGroupResp empty. 17 **GroupFetch** `[str group][str memberID][u64 generation]` + Fetch's exact entry/maxWait/maxBytes tail → answered by FetchResp (type 4, reused — one decode path). Codes 12 STALE_GENERATION, 13 UNKNOWN_MEMBER activate. |
| D-SL2-2 | **Why GroupFetch is a NEW type (design-tension note, reframed per review):** the FORCING FUNCTION is DD-12 vs the Fetch body — DD-12 requires group fetches to CARRY (memberID, generation), and the shipped Fetch shape (final per SL0's G7) has no such fields; a new additive type is the only move that honors both locked facts. This SUPERSEDES DD-15's prose picture of the member using Fetch itself for its owned partitions ("one fetch conn" property is preserved exactly — GroupFetch carries the same multi-entry tail). Honest corollary: raw multi-entry Fetch (2..16 entries, the G7 closure) has NO shipped-client caller — it is validated by the wake test only. Both facts logged here as the paper trail for SL6's PROTOCOL.md registry work. |
| D-SL2-3 | **Coordinator: `internal/group`, one mutex, injectable clock.** State: `groups[name] = {topic, generation, members[id]{generation, lastBeat, assignment}, committed[partition]next}`. All transitions under one mutex, never held during I/O or parking (DD-25). `Config{HeartbeatInterval 500ms, SessionTimeout 2s, SweepInterval 100ms, Clock}` — the clock is DESIGN §9's seam; GRP-2's bound test runs on a fake clock, no real sleeps. Liveness (DD-10, the CONNECTION not the message type): control-conn drop = immediate death; sweeper marks dead on missed session deadline; **ANY validly-fenced request from a live member on its control conn (Join/Heartbeat/Commit/Leave, at validation time) refreshes `lastBeat`** — an in-flight commit is itself liveness evidence, so a slow commit can never starve liveness (residual, stated: a single request stalled server-side past 2 s still dies — accepted). **Membership events = NEW-member join, leave, death — a re-Join is NOT one** (see D-SL2-3b): each bumps generation + recomputes range assignment (sorted memberIDs × contiguous ranges) immediately (DD-11). **REJOIN is LEVEL-TRIGGERED, never a consumable flag:** each member records the generation it last joined at; HeartbeatResp bit0 = (member.generation ≠ group.generation) — a flag cleared on delivery can be lost; a level derived under the mutex cannot. MemberIDs coordinator-assigned (`m<seq>`, unique per broker lifetime — restart forgets everything, DD-12's auto-fencing). |
| D-SL2-3b | **Re-Join identity via conn binding (review F2 — without this, rebalance livelocks).** A JoinGroup arriving on a conn already bound to a LIVE member of that group is that member's re-Join: same memberID returned, CURRENT (generation, assignment, committed) served, **no generation bump, no membership event** — the generation settles and GRP-2's bound is meetable. A conn whose bound member was swept dead (e.g. SIGSTOPped past deadline) is treated as a fresh join (new memberID — the old one stays fenced). |
| D-SL2-4 | **`data/_groups/` is RESERVED storage, and Store.Open must not eat it.** DD-13 puts commits in `data/_groups/<group>.json`. Store.Open currently REMOVES any data-dir entry lacking `meta.json` (aborted-create cleanup) — unguarded, every boot would DELETE all group commits. Rule: Open skips the literal name `_groups` (collision-impossible: DD-18 names must start `[a-z0-9]`). A test stages `_groups` + a junk meta-less dir and proves exactly one survives boot. The coordinator owns everything under `_groups/`. |
| D-SL2-5 | **Commit path (CONS-3): atomicWrite BEFORE ack, one file per group — merge INSIDE the commit lock (BOTH seats independently caught the lost-update).** `{"topic":T,"offsets":{"0":n,...}}` (offsets = next-to-read). Order, pinned: acquire per-group **commitLock** → mutex{validate fencing · snapshot CURRENT committed map · merge this commit} → unmutex → atomicWrite `_groups/<group>.json` → mutex{**re-validate member+generation — a member fenced mid-write gets 12/13 and NO ack, nothing installed** · install merged map} → unmutex → release commitLock → ack. Lock order pinned globally: commitLock→mutex, NEVER mutex→commitLock (deadlock otherwise). Because every committer merges onto the latest installed map under the commitLock, concurrent same-group committers cannot erase each other's acked partitions (a `-race` two-committer test proves it). Commits for partitions outside the member's current assignment → STALE_GENERATION. **Lazy load, two-phase, once per group per boot (F8):** first JoinGroup installs a loading placeholder under the mutex → releases → reads the file → reacquires → installs → wakes blocked joiners; a live group NEVER re-reads disk. Coordinator init runs `MkdirAll(data/_groups)` before any write (atomicWrite's temp lives in the destination dir). Unreadable/corrupt commit file → refuse the join loudly (MALFORMED naming the file), never guess positions. |
| D-SL2-6 | **Fencing at serve time (DD-12), exactly two errors — and Heartbeat is EXEMPT from the generation fence (F1: DD-12 fences fetches and commits; fencing heartbeats would make REJOIN undeliverable and falsely sweep live members mid-rebalance).** GroupFetch/CommitOffsets: group unknown OR memberID not live → UNKNOWN_MEMBER (13) · generation ≠ current → STALE_GENERATION (12); zero state change on either. Heartbeat: unknown member → 13 (restart auto-fencing needs it); known member → refresh `lastBeat`, respond with the level-triggered REJOIN bit (D-SL2-3) — NEVER 12. Consequence, pinned for tests: a swept-dead member's later commit always sees 13 (it left the live set); 12 is reachable only by a LIVE member (e.g. a parked GroupFetch waking across a rebalance). A parked GroupFetch re-validates on EVERY wake. JoinGroup on an existing group with a different topic → MALFORMED("group <g> is bound to topic <t>") — D15. JoinGroup with unknown topic → UNKNOWN_TOPIC. Caps: groups ≤ 64, members/group ≤ 32 → CAP_EXCEEDED; group name → INVALID_NAME (DD-16/18). |
| D-SL2-7 | **Multi-partition serving = `TryFetch` + goroutine-per-entry park (no reflection, no SL0 refactor) — send discipline pinned (F4: the naive version leaks a goroutine per park round).** New storage API: `Partition.TryFetch(offset, maxBytes) (recs, notifyCh, err)` — the read + channel-capture atomically under the read lock (a mechanical extraction of Fetch's existing pattern, same missed-wakeup pin). The broker's fetch loop: TryFetch every entry (maxBytes budgeted across the whole response, request order) → any records: respond · none: park one goroutine per entry on `select{<-notifyCh, <-done}`; **the wake chan is buffered to len(entries)** so a multi-wake round can never block a loser mid-send where `close(done)` can't reach it; **`done` is FRESH per park round** (reuse = double-close panic); the parent selects `{<-wake, <-timer, <-stopping, <-cancel}` and closes `done` on EVERY exit path → loop. Entries ≤ 16 bounds everything. **Empty response shape pinned (F7): FetchResp always carries exactly one group per requested entry, in request order, zero recs when empty** — the shipped single-entry shape is the n=1 case, both paths bytewise-identical semantics, stop shape (D-SL0-6) preserved verbatim. Raw single-entry Fetch keeps its existing `Partition.Fetch` path UNTOUCHED; raw multi-entry (2..16) and GroupFetch share the new loop. GroupFetch re-fences each iteration (D-SL2-6). |
| D-SL2-8 | **Client `GroupConsumer` (DD-19): two conns, rejoin-and-reissue — and the heartbeat goroutine NEVER re-joins (F6: auto-heal in the background races the fenced operation the test/user must observe).** Control conn: Join → heartbeat every 500 ms; a mutex serializes heartbeat/commit roundtrips (one-request-in-flight per conn); a slow commit cannot starve liveness because the SERVER counts it as liveness evidence (D-SL2-3). The heartbeat goroutine only RECORDS a rejoin-needed condition (REJOIN bit, or 13 on heartbeat); the actual re-Join happens lazily inside the next Poll/Commit — and **a fenced Commit SURFACES its error to the caller (pinned public contract), then the next call re-joins**; a fenced Poll re-joins and reissues internally (fetch data is not a caller-visible promise the way an acked commit is). Fetch conn: GroupFetch over ALL owned partitions from per-partition `next` cursors; fetch-conn read-deadline expiry (maxWait + grace) is conn-fatal → redial + rejoin. API: `JoinGroup(addr, group, topic) (*GroupConsumer, error)` · `Poll(maxWait) ([]PartRecord, error)` · `Commit() error` · `Close()` (LeaveGroup + both conns). Deadlines wrap wire I/O only (DD-19). |
| D-SL2-9 | **Scenario C completion in the harness — one-directional, like SL1, and EXACTLY ONE member (F9: load-bearing precondition).** The kill -9 harness adds a single group-consumer goroutine (shipped client): consume, commit per batch, journal every ACKED commit (partition → next). After each restart: JoinGroup returns recovered committed offsets; assert recovered ≥ journaled per partition (commit acked ⇒ durable ⇒ never lower FOR A SINGLE MEMBER; with ≥2 members a live current-generation member may legally commit a lower position after reassignment — the ≥ assertion is unsound there, so this harness pins one member and says why). |
| D-SL2-10 | **Scenario E live (SD-11) on REAL `mk consume -g` processes — the surface SLICES' locked demo line names.** Live procedure (receipted, `docs/receipts/sl2-scenario-e.txt`): broker + topic (4 partitions) + producer feed → two `mk consume -g grp` processes split the partitions → SIGSTOP one → real-time wait past the 2 s session → survivor's re-join shows it owns all 4 → SIGCONT → the woken process's next commit surfaces UNKNOWN_MEMBER (13 — deterministic per D-SL2-6: swept members always see 13; the client surfaces it per D-SL2-8), visible in its output, group positions unchanged by it. Deterministic legs live as broker-level tests (fencing suite) + an e2e two-member client test asserting takeover + the GRP-3 union (§5). Scenarios D and F are plain client tests (restart-resume exact offset; second group full stream from 0). |
| D-SL2-11 | **Server → coordinator lifecycle glue.** JoinGroup binds memberID to its conn; the server's existing per-conn teardown calls `coord.ConnClosed(connID)` → immediate death + rebalance (DD-10 control-conn-drop). Heartbeats keep control conns busy, so SL4's future idle reclaim can never kill them (DD-24 note, no code here). Graceful stop: coordinator returns SHUTTING_DOWN to group requests during drain — parked group fetches already return empty via the stopping channel (D-SL0-6 unchanged). |

## 3. Crash/failure-point analysis (the rows groups add to DESIGN §7)

| Failure mid… | Outcome |
|---|---|
| commit atomicWrite | Old or new file, never torn (DD-13); unacked → client may re-commit → same value, idempotent (R2-class, correct) |
| broker kill -9 with commits in flight | Acked commits durable (harness-proven); unacked lost → re-delivery from last commit (GRP-3 at-least-once, exactly the spec's promise) |
| member SIGKILL/SIGSTOP | Session deadline (2 s) → death → generation bump → survivor assignment ≤ 1 s later (GRP-2); late riser fenced at serve time (GRP-5) |
| rebalance vs parked fetch | Parked GroupFetch re-fences on wake → STALE_GENERATION → client rejoins (DD-12; no generation-bump wake needed) |
| broker restart | Membership forgotten (all pre-crash memberIDs unknown → fenced); commits reloaded from `_groups/` on first join; boot NEVER deletes `_groups` (D-SL2-4) |
| coordinator sweep vs heartbeat race | Both under the one mutex — a heartbeat at t=deadline either lands before the sweep (member lives) or after (fenced on its next call); no torn state either way |

## 4. Known gaps accepted

- **G-SL2-1** — `mk consume -g` is the MINIMAL group CLI (join/poll/print/commit-per-batch): no offset override, no assignment display beyond printed records, no group admin (list/delete groups doesn't exist anywhere — not spec'd). SL6 owns any final CLI polish.
- **G-SL2-2** — commit files are per-group JSON, rewritten whole per commit batch: fine at D4's per-batch rate and ≤16 partitions; stated in the file's doc comment. Not a mechanism for high-rate commits, by design (spec D4).
- **G-SL2-3** — GRP-2's 1 s detection→assignment bound is proven on the fake clock + observed e2e; the 500 ms/2 s defaults themselves stay compile-time constants in `group.Config` defaults (no flags — NFR-2's cap discipline: nothing new user-tunable without a cap).
- **G-SL2-4** — the SD-11 receipt's SIGSTOP timing uses real wall-clock (2 s+ sleeps in one e2e test): accepted, it is the REALISM leg; the deterministic leg is the fake-clock bound test.

## 5. Test plan mapped to claims

- **Coordinator unit (fake clock):** GRP-1 exact-partition (2×4, generation-tagged) · GRP-2 bound (advance past deadline → sweep → new generation within 1 s of detection; measured on the fake clock) · NEW-member join/leave/death each bump generation once; **a re-Join bumps NOTHING and returns the same memberID (D-SL2-3b — the livelock guard)** · REJOIN bit is level-triggered: visible on every heartbeat until re-Join, and a heartbeat during rebalance refreshes lastBeat (F1's false-sweep case) · caps (65th group, 33rd member) → CAP_EXCEEDED · one-topic-per-group violation → MALFORMED.
- **GRP-3 union (named owner — review made this test exist):** two members × 4 partitions over real TCP, produce N, SIGKILL-equivalent one member mid-batch BEFORE its commit, rebalance completes, survivor consumes on; union of records processed across BOTH members' lifetimes == all N produced (dupes legal, loss fatal).
- **Commit concurrency (`-race`):** two members of one group commit disjoint partitions concurrently → no committed partition regresses, file and map agree (the BOTH-seats lost-update catch, D-SL2-5).
- **Fencing (broker-level, real TCP):** stale-generation fetch + commit → 12; unknown member → 13; zero state change proven by re-reading positions; PROT-3 rows: broker serves normal traffic after every rejection.
- **Commit path:** CONS-2 consume-half/commit/restart-consumer resumes exactly · CONS-3 via harness (D-SL2-9) · commit-outside-assignment → STALE_GENERATION · corrupt `_groups/<g>.json` → join refused loudly · `_groups` survives boot while junk dirs are removed (D-SL2-4).
- **Multi-partition wake:** parked multi-entry fetch (raw AND group) wakes on ANY listed partition's frontier advance, not on raw append (extends SL0's wake test through the new loop); goroutine-leak check via ParkedWaiters + `-race`.
- **Scenarios:** C = harness with commits (D-SL2-9) · D = restart-resume test · E = SD-11 re-exec test (+ live `-v` receipt) · F = second-group-from-0 test.
- **Client:** GroupConsumer rejoin-and-reissue on REJOIN and on STALE (kill the assignment under it mid-poll); control-conn serialization race test under `-race`.
