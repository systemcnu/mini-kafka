# SL5 Slice Design — Benchmarks

**Status: FINALIZED (2026-07-30) after 2-seat independent review (buildability + different-model coverage) — 16 findings (10+6, THREE convergences: the smoke test's "every field non-zero" was unsatisfiable for legitimately-zero counters; the README↔report gate had no bootstrap story before the reference run exists; the broker's 5 ms group-commit window — the very thing that shapes every headline number — was missing from the labels). Worst solo catch: `go run` embeds no VCS info, so the reference run as commanded would have emitted a report with an EMPTY commit field — traceability broken precisely at the exit demo while the binary-building smoke test stayed green.**

## 2. Slice-local decisions

| # | Decision |
|---|---|
| D-SL5-1 | **Harness topology & measurement (DD-22 realized).** One process: broker in-process on `127.0.0.1:0`, data dir `os.MkdirTemp`, topic `bench` × 4 partitions. Closed loop: C=8 `client.Producer`s, one goroutine each, producer *i* → partition *i* mod 4, 1 KiB payloads, sync produce (in-flight = 1 per conn — that IS the closed loop; verified true of the shipped client). Payload embeds `(producerID, perProducerSeq, sendUnixNano)` — the ID pair is the dedupe key (F5: a bare per-producer counter collides eight ways and reports garbage duplicates). End-to-end: ONE `client.GroupConsumer` polling throughout; e2e latency = receipt time − embedded send time, same process so no skew (wall-clock steps accepted noise, stated in the method note). **Sample attribution pinned (F8):** iteration index published atomically; ack samples bucket by ack-COMPLETION time, e2e samples by RECEIPT time; the warm-up bucket is measured and discarded (stated). **Consumer commit cadence pinned (F6):** `Commit()` once per iteration boundary, OUTSIDE the measured loop — per-poll commits would stall delivery behind two extra fsyncs and contend with the produce path; never committing would mass-rewind on any spurious rejoin. Stated in the method note. Iterations: 2 s warm-up then ≥3 × 10 s, one broker lifetime. Percentiles: nearest-rank on the full sorted per-iteration sample. |
| D-SL5-2 | **The report is the single source of truth; the schema is the BENCH-2 checklist — complete this time (CF4).** `benchmarks/reports/<utc-date>-<commit>.json`, one struct: title ("closed-loop response latency"), commit (+dirty marker), timestamp, hardware (flag), os/arch, go version, GOMAXPROCS, storage note (flag, default "local SSD (unverified)"), fsync mode ("fsync" + DD-7 caveat), **batching: `group_commit_window_ms: 5` (F4/CF2 — the broker's flusher waits out a 5 ms window and pays three fsyncs per flush; ack latency floors there, and BENCH-2's literal "batching/in-flight settings" demands it labeled)**, load model ("closed-loop, C=8 sync producers, in-flight 1/conn"), message size, partitions, warm-up, run duration, **percentile_method ("nearest-rank on sorted samples")**, per-iteration rows (duration, msgs acked, msgs/s, MB/s, ack p50/p99, e2e p50/p99, e2e samples, GC pause Δ, GC count Δ, produce errors, duplicates), cross-iteration spread (min/max/mean of msgs/s and both p99s), caveats block (closed-loop understates queueing tails · ack latency includes the 5 ms group-commit window · fsync platform limit · no capacity claims). **Duplicates are counted AND excluded (F7):** first delivery of an ID contributes its e2e sample and throughput; re-deliveries only increment the duplicates counter — a redelivered record carries its original timestamp and would poison p99 with seconds-scale re-read artifacts. |
| D-SL5-3 | **Flags.** `-hardware "<string>"` REQUIRED (refuse to run without it). `-storage "<string>"` optional, honest default above. Test seams (demo `-flow` precedent): `-iters` (3), `-duration` (10 s), `-warmup` (2 s), `-c` (8), `-out <dir>` (default `benchmarks/reports`). `-render-readme <report.json>` renders instead of benchmarking; `-readme <path>` names the README (default `README.md` — path resolution pinned in the plan, F9). |
| D-SL5-4 | **README section + the BENCH-3 gate, with its bootstrap pinned (F3/CF5 convergence).** Marker-delimited section (`<!-- bench:begin -->`/`<!-- bench:end -->`) rendered as a pure function of the named report, carrying INLINE (CF1): the headline table (throughput, ack p50/p99, e2e p50/p99, spread) · the FULL label block (hardware, OS/arch, Go, GOMAXPROCS, commit, storage, fsync mode, batching window, load model, message size, duration×iterations, warm-up, percentile method) · error and duplicate counts beside the numbers they qualify · both caveats · the source report path. The gate test (`cmd/bench/render_test.go`): golden-path fixture leg always runs; the real-README leg's rule — **if `benchmarks/reports/` holds no committed report, SKIP with a named reason (pre-reference bootstrap state); once any report is committed, markers must exist, the named report must exist, and the re-render must byte-compare** — so the builder's suite is green before the reference run, the integrator's commit arms the gate permanently, and deleting the section later (with reports present) is a failure, not a silent skip. Rendering determinism: same report → byte-identical section. |
| D-SL5-5 | **What the bench does NOT do or claim (reworded per F10).** No open-loop mode, no capacity/"max" claims (R5 accepted) · no comparisons to other systems · **CI never runs a benchmark whose report is committed or published — the smoke test's short run in CI is ephemeral and its report is discarded; shared-runner numbers never reach the repo** · commit cadence is fixed by D-SL5-1, not benchmarked. |
| D-SL5-6 | **Reference run = scenario G = the committed artifacts.** The integrator runs the defaults on Sri's actual machine (consistent with SLICES' "Sri's reference run on stated hardware" — the seat verified this reading) via a BUILT binary or `-buildvcs=true` (D-SL5-8), commits the report, runs `-render-readme`, captures `docs/receipts/sl5-scenario-g.txt`. The README names that exact report file. |
| D-SL5-7 | **What SL5 touches.** NEW: `cmd/bench` (+ tests), `benchmarks/reports/` (the one committed reference report), the README bench section, receipts. NO broker, client, wire, storage, group, or CI-workflow changes (the gate test rides the existing test job). |
| D-SL5-8 | **Commit provenance is enforced (F1 — the worst catch).** The harness reads `debug.ReadBuildInfo` for `vcs.revision`/`vcs.modified` and REFUSES to run a report-emitting benchmark when the revision is absent, with an error naming the fix (`go run -buildvcs=true ./cmd/bench` or a built binary) — plain `go run` embeds no VCS info (probed on this repo's toolchain), so the naive command would ship a report with an empty commit label and a filename of `<date>-.json`. A modified tree stamps `<hash>-dirty` into commit and filename; the render gate additionally asserts the COMMITTED reference report is not dirty-stamped (a published number must trace to a real commit). The smoke test covers the refusal path. |

## 3. Known gaps accepted

- **G-SL5-1** — hardware and storage labels are operator-stated flags, not detected: honest self-description is the design; the default storage string says "(unverified)" so a lazy run is labeled as such.
- **G-SL5-2** — wall-clock e2e: a clock step mid-iteration lands in the numbers; same-process measurement makes this rare and small; method note states it.
- **G-SL5-3** — the consumer measures e2e only for records received in-window; if it lags, latency inflates HONESTLY and the per-iteration e2e sample count exposes it.
- **G-SL5-4** — the committed reference report goes stale between refreshes **because honest hardware labels and CI runners are irreconcilable (CF6-reworded: CI cannot re-run this the way it re-runs demo-timing — a shared-runner number under a false hardware label would be worse than a stale honest one).** The rendered section carries its report's commit; freshness rests on the human refresh, stated plainly. |

## 4. Test plan mapped to claims

- **Smoke test** (`cmd/bench/bench_test.go`, black-box, built binary): short seams (`-iters 2 -duration 1s -warmup 200ms -c 2`), required `-hardware`, temp `-out`; assert exit 0 · report exists and unmarshals · **field assertions in TWO classes (F2/CF3 convergence): must-be-positive (msgs acked, msgs/s, MB/s, ack/e2e p50≤p99 present, e2e samples, durations, every label string incl. percentile_method and the batching window) vs present-may-be-zero via RAW-JSON key presence (produce errors, duplicates, GC deltas — unmarshaled zero and missing are indistinguishable, so presence is checked on the JSON text/keys)** · healthy-run sanity: `errors == 0 && duplicates == 0` · iterations == 2, spread block present, caveats carry the closed-loop + batching-window + fsync texts · `-hardware` absent → distinct refusal, non-zero exit · VCS-absent refusal path (F1) exercised where stageable.
- **Render tests** (`render_test.go`): fixture leg — render a fixture report, assert numbers + labels + counts inline and the path named; determinism (twice → byte-identical); **real-README leg per D-SL5-4's bootstrap rule** (skip named while no report is committed; full byte-compare + not-dirty assertion after).
- **Live legs (exit, integrator):** scenario G reference run (built binary, defaults, real hardware string) → committed report + README render + transcript receipt · exit sabotage: hand-edit one README number → gate red → restore via `-render-readme` → green.
